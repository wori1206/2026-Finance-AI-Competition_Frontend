그 화면을 고칠 때도 새로 쓰는 부분은 이 규칙을 따릅니다.

## 1. 원칙

- **시안이 기준입니다.** 시안 요소를 임의로 빼지 않고, 시안에 없는 기존 기능은 지우지 않습니다(빼야 하면 먼저 묻기).
- **판정 이름은 바꾸지 않습니다.** 가능 · 확인 필요 · 불가 · 점검 전 · 점검 중 — 시안이 「확인필요」처럼 붙여 써도 코드는 띄어 씁니다.
- **내부 값은 화면에 내지 않습니다.** 문장 ID · 검증코드 · 사유 코드는 쉬운 한국어로 바꿉니다.
- **글꼴은 Pretendard** 입니다(Figma 는 Noto Sans KR 이지만 바꾸지 않기로 함). 크기 · 굵기 · 색만 시안 값을 씁니다.
- **hex 를 직접 쓰지 않습니다.** 아래 토큰(`app/globals.css`)을 쓰고, 없는 색이 반복되면 토큰을 먼저 추가합니다.
  한 화면에서 한 번만 쓰는 시안의 미세한 글자 · 선 색(예: `#536058`)은 그 화면 CSS 안에서만 허용합니다.

## 6. 용어 · 문구

- 판정: **가능 · 확인 필요 · 불가**, 점검 상태: **점검 전 · 점검 중**, v070 화면 전용: **확인 완료**.
- 일정 종류: **사전 준비 · 집행 · 완료** (배지는 「준비」 「집행」).
- 규정 용어는 그대로: 비목 · 세목 · 주관기관 · 협약 · 자기부담금.
- 날짜: 목록 `9/9`, 문장 `9월 9일`, 표 `2026.09.30`, 남은 날 `D-3` · `D-DAY`, 지난 날 「기한 지남」 · 「N일 지남」.
- 이미 배포된 버튼 글자는 바꾸지 않습니다(바꿔야 하면 먼저 묻기).

## 7. CSS 작성 규칙

- 화면 단위로 파일을 하나 둡니다: `app/<화면>-v###.css`, `app/checkumait-app.tsx` 맨 위 import 목록 **끝**에 추가합니다.
- 선택자는 `.app-shell .<화면 클래스>` 로 범위를 좁혀 다른 화면에 새지 않게 합니다.
- `!important` 는 옛 파일(`semantic-colors.css` · `final-overrides.css`)의 `!important` 를 덮을 때만 씁니다.
- 색은 §2 토큰을 씁니다. 반복되는 새 색은 `app/globals.css` 토큰 블록에 먼저 추가합니다.
- 바꾸면서 읽는 곳이 없어진 클래스의 CSS 는 같은 작업에서 지웁니다(`grep` 으로 tsx 사용처 0 확인).
- 바꾼 이유는 주석 `/* v###: … */` 로 남깁니다.

## 8. 작업 순서와 확인

1. Figma 에서 해당 프레임을 열어(Figma MCP `get_design_context`) 값과 화면을 받습니다.
2. 기존 컴포넌트 · 클래스 · 토큰을 먼저 찾고, 없을 때만 새로 만듭니다.
3. 정할 것(시안에 없는 기존 기능, 문구, 데이터가 없을 때 모양)은 구현 전에 묻습니다.
4. 모의 서버 + Playwright 로 1280 폭 캡처를 찍어 Figma 캡처와 **항목별로 대조**하고, 차이를 표로 보고합니다.
   스크립트: `써도돼요_작업도구\pw\mock\design_now.mjs` (홈 · 지출 계획 · 집행 일정, `OUT=접두어`).
5. 모양이 바뀌면 안 되는 정리 작업은 전후 캡처를 픽셀 비교합니다(v074 토큰 정리 때 세 화면 모두 동일 확인).
6. `npx tsc --noEmit` 통과, `npx eslint app lib` 건수가 main 보다 늘지 않을 것, 브라우저 콘솔 오류 없을 것.
